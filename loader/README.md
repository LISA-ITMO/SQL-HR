# Загрузчик CSV в таблицу `candidates`

Прототип для задачи #28. Загружает CSV с кандидатами в уже работающую базу SQL-HR по файлу соответствия колонок (YAML). Поиск, агент и интерфейс остаются прежними: после загрузки вопрос задаётся в обычном чате.

## Что делает

- читает CSV (UTF-8; разделитель по умолчанию `;`, другой задаётся флагом `--delimiter`) и файл соответствия;
- для каждой записи пишет в базу `source_file` (имя CSV) и `source_row` (номер записи в CSV: заголовок = 1, первый кандидат = 2 и т. д.). Записи с многострочными ячейками считаются как одна;
- поле, которого нет в соответствии, остаётся пустым: выдуманные значения не подставляются;
- число дипломов пишется как 0, только если их отсутствие указано явно. Если «да» нет, а часть сведений неизвестна (пусто, «неизвестно»), пишется NULL;
- перед загрузкой показывает отчёт: сколько записей принято и отклонено, заполненность каждого поля, неиспользованные колонки, предупреждения;
- предупреждает, если у всех записей пустое поле, по которому поиск фильтрует по умолчанию (дата рождения, образование, гражданство, статус, готовность);
- останавливается, если колонок из соответствия нет в CSV (загрузить всё равно можно с флагом `--allow-missing-columns`, такие поля останутся пустыми);
- записи с неверной датой или числом, а также со сломанным числом колонок не загружает, а пишет в `data/<имя>.rejected.csv` (номер записи, причина, колонка, значение);
- не загружает один и тот же файл дважды. Чтобы перезагрузить, нужен `--replace`: он удаляет только записи этого файла;
- если ни одна запись не принята, загрузка останавливается и прежние записи не удаляются. Удаление и вставка идут в одной транзакции, поэтому при ошибке записи старые данные сохраняются.

## Подготовка

```bash
python3 -m venv .venv-loader
source .venv-loader/bin/activate
pip install pyyaml psycopg2-binary
```

База должна быть запущена (`docker compose up -d`). Параметры подключения читаются из `.env`, хост по умолчанию `localhost`.

## Запуск

Команды выполняются из корня репозитория с активированным `.venv-loader`. Все флаги: `python loader/load_csv.py --help`.

Файл соответствия подбирается по имени CSV: для `candidates_b.csv` берётся `loader/mappings/candidates_b.yaml`. Другой YAML можно передать флагом `--mapping`.

Сначала проверка без записи в базу:

```bash
python loader/load_csv.py loader/examples/candidates_b.csv --dry-run
```

Затем загрузка:

```bash
python loader/load_csv.py loader/examples/candidates_b.csv
```

Перезагрузка того же файла: добавить `--replace`. Удалить загруженное вручную:

```sql
DELETE FROM candidates WHERE source_file = 'candidates_b.csv';
```

Найти, из какой строки файла пришёл кандидат:

```sql
SELECT last_name, first_name, source_file, source_row FROM candidates WHERE last_name = 'Иванов';
```

Колонки `source_file` и `source_row` загрузчик добавляет сам (`ADD COLUMN IF NOT EXISTS`), в `db/schema.sql` они тоже есть для новых баз.

## Тесты

```bash
pip install pytest
python -m pytest loader/tests
```

Тесты автоматически проверяют то, что легко сломать незаметно: подсчёт дипломов (да, нет, пусто, «неизвестно» и их сочетания в нескольких колонках) и сохранность данных при `--replace` (полностью битый файл не стирает старые записи, замена трогает только записи своего файла, ошибка записи в базу откатывает удаление). Кроме того, тесты сами находят все CSV в `data/` и `loader/examples/`, для которых в `loader/mappings/` есть YAML с тем же именем, и прогоняют их через загрузчик: так ловятся опечатки в YAML и проверяется, что `source_row` указывает на ту строку файла, откуда взята запись. Если всё в порядке, в конце будет `passed`. Если что-то сломано, будет `failed` с названием теста, по которому видно, какая проверка не прошла. Запускать их стоит после любой правки `load_csv.py`. Тестам замены нужна запущенная база: они работают во временной схеме и удаляют её за собой, рабочие данные не трогают. Если база не запущена, эти тесты пропускаются (`skipped`), а не падают.

## Статус прототипа

Загрузчик пока отдельный скрипт, который запускают вручную из терминала. В `agent_server`, `frontend` и `docker-compose.yml` он не встроен: интерфейса загрузки (кнопки в чате) и автоматического запуска нет.

## Файл соответствия

```yaml
fields:
  last_name: "surname"                 # поле: "колонка CSV"
  birth_date: "birth"                  # даты читаются в форматах yyyy-mm-dd, dd.mm.yyyy, dd-mm-yyyy, dd/mm/yyyy
  work_text:
    columns: ["employer", "position"]  # несколько колонок склеиваются в текст «колонка: значение; …»
  education_count:
    type: count_true                   # сколько колонок отмечено True/да/1 (пусто/неизвестно → NULL, см. выше)
    columns: ["has_diploma"]
```

Типы: `text` (по умолчанию), `date`, `number`, `int`, `count_true`, `experience_years` (стаж по двум датам), `citizenship` («РФ», если в тексте есть россия/россии/рф). Примеры в `loader/mappings/`: `candidates_synth.yaml` (исходный формат, те же поля, что заполняет `db/add_rows.sql`), `candidates_b.yaml` (другие названия колонок), `candidates_c_minimal.yaml` (в файле нет полей, нужных поиску).

## Ограничения

- Грузятся только поля, которые есть в таблице `candidates` (29 полей). Всё остальное, что есть в CSV, в базу не попадает. Для исходного файла это 48 колонок из 108.
- Новое поле, которого нет в `candidates`, потребует изменения схемы, а затем и агента (`QuerySpec`, `get_from_query`).
- Поиск по умолчанию скрыто фильтрует по возрасту 20–65, образованию, гражданству РФ, статусу «резервист» и готовности «годен» (`agent_server/main.py`, `get_from_query`). Если этих данных в CSV нет, чат ничего не найдёт, и загрузчик об этом предупреждает.
- Свободный текст (образование, работа, прочее) лежит в трёх текстовых полях, поиск по нему идёт через `ILIKE`. Формат склейки не совпадает с форматом `db/add_rows.sql`, поэтому ответы по одним и тем же людям могут слегка отличаться.
- Гражданство определяется по тексту паспорта, как в `add_rows.sql`. Если слов «Россия/РФ» там нет, кандидат считается не РФ.
- В карточке кандидата в чате `source_row` пока не показывается, его видно в базе. Показ в чате потребует правок в `agent_server` и интерфейсе.
- Нужен CSV с одной строкой заголовка. Один файл — одно соответствие.
