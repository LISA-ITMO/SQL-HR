# Загрузчик CSV в таблицу `candidates`

Прототип для задачи #28. Загружает CSV с кандидатами в уже работающую базу SQL-HR по файлу соответствия колонок (YAML). Поиск, агент и интерфейс остаются прежними: после загрузки вопрос задаётся в обычном чате.

## Что делает

- читает CSV (UTF-8, разделитель `;`, по умолчанию) и файл соответствия «поле таблицы → колонка CSV»;
- для каждой записи пишет в базу `source_file` (имя CSV) и `source_row` (номер записи в файле, заголовок = 1, первый кандидат = 2). Записи с многострочными ячейками считаются как одна;
- не придумывает значения: поле, которого нет в соответствии или в CSV, остаётся пустым;
- перед загрузкой показывает отчёт: сколько записей принято и отклонено, заполненность каждого поля, неиспользованные колонки, предупреждения;
- предупреждает, если у всех записей пусто поле, по которому поиск фильтрует по умолчанию (дата рождения, образование, гражданство, статус, готовность);
- останавливается, если колонок из соответствия нет в CSV (выбрано не то соответствие);
- записи с неверной датой или числом, а также со сломанным числом колонок не загружает, а пишет в `data/<имя>.rejected.csv` (номер записи, причина, колонка, значение);
- не загружает один и тот же файл дважды. Чтобы перезагрузить, нужен `--replace`: он удаляет только записи этого файла.

## Подготовка

```bash
python3 -m venv .venv-loader
source .venv-loader/bin/activate
pip install pyyaml psycopg2-binary
```

База должна быть запущена (`docker compose up -d`). Параметры подключения (`POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_PORT`) читаются из `.env`, хост по умолчанию `localhost`. Пароль можно передать и так: `POSTGRES_PASSWORD=... python loader/load_csv.py ...`. Пароли и `.env` в Git не добавляем.

## Запуск

Файл соответствия подбирается по имени CSV: для `candidates_b.csv` берётся `loader/mappings/candidates_b.yaml`. Другой YAML можно передать флагом `--mapping`.

Сначала проверка без записи в базу:

```bash
python loader/load_csv.py loader/examples/candidates_b.csv --dry-run
```

Затем загрузка:

```bash
python loader/load_csv.py loader/examples/candidates_b.csv
```

Перезагрузка того же файла: добавить `--replace`. Удалить загруженное вручную:

```sql
DELETE FROM candidates WHERE source_file = 'candidates_b.csv';
```

Найти исходную строку для результата:

```sql
SELECT last_name, first_name, source_file, source_row FROM candidates WHERE source_file = 'candidates_b.csv';
```

Колонки `source_file` и `source_row` загрузчик добавляет сам (`ADD COLUMN IF NOT EXISTS`), в `db/schema.sql` они тоже есть для новых баз.

## Статус прототипа

Загрузчик пока отдельный скрипт, который запускают вручную из терминала. В `agent_server`, `frontend` и `docker-compose.yml` он не встроен: интерфейса загрузки (кнопки в чате) и автоматического запуска нет. Следующий шаг, если он понадобится: загрузка файла из интерфейса, выбор соответствия колонок и вывод отчёта загрузчика в чате.

## Файл соответствия

```yaml
fields:
  last_name: "surname"                 # поле: "колонка CSV"
  birth_date: "birth"                  # даты читаются в форматах yyyy-mm-dd, dd.mm.yyyy, dd-mm-yyyy, dd/mm/yyyy
  work_text:
    columns: ["employer", "position"]  # несколько колонок склеиваются в текст «колонка: значение; …»
  education_count:
    type: count_true                   # сколько колонок отмечено True/да/1
    columns: ["has_diploma"]
```

Типы: `text` (по умолчанию), `date`, `number`, `int`, `count_true`, `experience_years` (стаж по двум датам), `citizenship` («РФ», если в тексте есть россия/россии/рф). Примеры: `mappings/candidates_synth.yaml` (исходный формат, повторяет `db/add_rows.sql`), `candidates_b.yaml` (другие названия колонок), `candidates_c_minimal.yaml` (в файле нет полей, нужных поиску).

## Ограничения

- Грузятся только поля, которые есть в таблице `candidates` (29 полей). Всё остальное, что есть в CSV, в базу не попадает. Для исходного файла это 48 колонок из 108.
- Новое поле, которого нет в `candidates`, потребует изменения схемы, а затем и агента (`QuerySpec`, `get_from_query`).
- Поиск по умолчанию скрыто фильтрует по возрасту 20–65, образованию, гражданству РФ, статусу «резервист» и готовности «годен» (`agent_server/main.py`, `get_from_query`). Если этих данных в CSV нет, чат ничего не найдёт, и загрузчик об этом предупреждает.
- Свободный текст (образование, работа, прочее) лежит в трёх текстовых полях, поиск по нему идёт через `ILIKE`. Формат склейки не совпадает с форматом `db/add_rows.sql`, поэтому ответы по одним и тем же людям могут слегка отличаться.
- Гражданство определяется по тексту паспорта, как в `add_rows.sql`. Если слов «Россия/РФ» там нет, кандидат считается не РФ.
- В карточке кандидата в чате `source_row` пока не показывается, его видно в базе. Показ в чате потребует правок в `agent_server` и интерфейсе.
- Нужен CSV с одной строкой заголовка. Один файл — одно соответствие.
