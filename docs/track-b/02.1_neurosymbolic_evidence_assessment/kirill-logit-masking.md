## Место в исследовании 02.1

Кирилл реализовал исследовательский компонент **«текст → фрагменты → компетенции из заданного каталога»**. Его можно сравнивать с другими способами извлечения в начале цепочки оценки соответствия роли.

Основная идея: вместо включения всего каталога в промпт использовать каталог для ограничения допустимых продолжений модели. Модель выбирает ключевые выражения или слова; их совместимость с каталогом сужает множество компетенций. После поиска отдельный вызов модели принимает или отклоняет предложенный вариант.

Для 02.1 это потенциальный способ уменьшить ошибки выбора сущностей и обеспечить проверяемую привязку к тексту. **Наличие допустимой компетенции и дословной цитаты ещё не доказывает достаточность свидетельства, личный вклад кандидата или соответствие роли.** Эти задачи остаются в основном методе 02.1.

## От исходной идеи к текущему коду

В репозитории сосуществуют две реализации. Их результаты и свойства нельзя объединять под названием одного неизменного пайплайна.

| Аспект | Исходный `ExtractionPipeline` | Актуальный `CompetencySelector` |
|---|---|---|
| Выбор компетенции | Токенная маска ключевых выражений; пересечение допустимых классов; раннее завершение при однозначности | Поиск по словам и леммам каталога; согласованные словесные сигналы; пул кандидатов, допускающий небольшую неоднозначную группу |
| Цитата | Генерация под `SourceSpanMask`: непрерывная последовательность токенов источника | Выбор готового предложения или объединённого короткого фрагмента по модельной оценке; символьные позиции в исходном тексте |
| Поддержка | `_score_support`: цитата + название компетенции + индикаторы; сравнение оценок полных вариантов ДА/НЕТ | `check`: текст + название компетенции; сравнение вероятностей первых токенов вариантов ДА/НЕТ |
| Уровни | Есть forced choice Б/С/П/UNKNOWN по якорям индикаторов | Оценки уровней в итоговой выдаче нет |
| Ролевой фильтр | Есть аргумент `role_id` | Индекс строится по всему каталогу; параметра роли у селектора нет |
| Где используется | CLI `run` / `evaluate`, ранние эксперименты, код трассировки | Текущий веб-сервис `/api/select`, режимы `quote_first` / `quote_last`, поздние эксперименты |

Источники: [`pipeline.py`](https://github.com/JGSnapp/krm-logit-mask/blob/d7db10cb5b1361e77862efe1e6091decec800bac/src/krm_mask/pipeline.py), [`selection.py`](https://github.com/JGSnapp/krm-logit-mask/blob/d7db10cb5b1361e77862efe1e6091decec800bac/src/krm_mask/selection.py), [`cli.py`](https://github.com/JGSnapp/krm-logit-mask/blob/d7db10cb5b1361e77862efe1e6091decec800bac/src/krm_mask/cli.py), [`server.py`](https://github.com/JGSnapp/krm-logit-mask/blob/d7db10cb5b1361e77862efe1e6091decec800bac/src/krm_mask/server.py).

### Исходный пайплайн: выражения и токенные маски

Из КРМ извлекаются компетенции, индикаторы, рекомендуемые темы, описания уровней и роли. `PhraseGraph` связывает допустимые выражения с компетенциями. Это индекс для управления декодированием, а не граф пререквизитов или готовый механизм логического вывода о кандидате.

`PhraseGraphMask` оставляет только токены, совместимые с допустимыми выражениями. Выражения можно выбирать в разном порядке; после выбора очередного выражения множество совместимых компетенций пересекается с предыдущим. Разрешается завершить выбор, когда компетенция определена однозначно, в том числе по префиксу без дописывания названия. Опциональный DISC повторяет пути с весами и резервным выбором; это дополнительная экспериментальная конфигурация, не обязательная часть позднего селектора.

`SourceSpanMask` разрешает продолжать цитату только по последовательным токенам хотя бы одного вхождения в источнике. Она не позволяет склеить несмежные фрагменты, но сама не гарантирует смысловую релевантность или удобные границы цитаты. В журнале эксперимента 22 описаны обрывки и начало внутри слова; позднее автор перешёл к выбору предложений.

Поддержку проверяет LLM, после чего другая forced-choice оценка выбирает Б/С/П/UNKNOWN по текстам якорей. Это ещё не исполняемые экспертные правила достаточности и не валидированная оценка уровней. `UNKNOWN` означает нехватку свидетельств.

Источники: [`graph.py`](https://github.com/JGSnapp/krm-logit-mask/blob/d7db10cb5b1361e77862efe1e6091decec800bac/src/krm_mask/graph.py), [`masking.py`](https://github.com/JGSnapp/krm-logit-mask/blob/d7db10cb5b1361e77862efe1e6091decec800bac/src/krm_mask/masking.py), [`disc.py`](https://github.com/JGSnapp/krm-logit-mask/blob/d7db10cb5b1361e77862efe1e6091decec800bac/src/krm_mask/disc.py).

### Текущий селектор: поиск, проверка и два порядка работы

`WordIndex` строится по индикаторам и ключевым словам. Слова приводятся к леммам; слова одного сигнала должны быть совместимы с одной фразой каталога, а разные сигналы сужают набор компетенций. Поиск поддерживает несколько путей, поправки на частотность/априорную вероятность и пакетные вычисления. Конкретные значения параметров менялись между экспериментами, поэтому для воспроизведения нужен соответствующий runner.

В `quote_last` поиск идёт по всему резюме. Для каждого кандидата проверка `check` вычисляет маржу между ДА и НЕТ; варианты с маржой выше порога ранжируются, затем выбираются до `max_competencies` ответов. После этого к каждому прикрепляется предложение, оценённое по средней логарифмической вероятности на токен с контрастной поправкой относительно запроса без названия компетенции.

В `quote_first` сначала оцениваются предложения резюме как возможные цитаты об опыте. По умолчанию берутся три фрагмента, по каждому ищется до пяти кандидатов; поиск может остановиться на группе до пяти компетенций после одного сигнала. Кандидаты объединяются и проверяются один раз на компетенцию. По умолчанию итог ограничен тремя компетенциями, поэтому текущий сервис не является исчерпывающим извлекателем всех навыков длинного документа.

**Важная деталь по коду:** в `select_quote_first` вызов `check(text, competency)` получает **всё исходное резюме**, а не выбранную цитату. В ответе остаётся первая цитата, по которой найден кандидат; дополнительные цитаты записываются как ссылки на их ранги. Поэтому ДА может быть основано на другом предложении резюме, а смысловая поддержка именно прикреплённой цитатой отдельно не проверяется. Общее описание «поиск только по свидетельству» в README не следует переносить на проверку этого режима.

`p_yes` — нормированное предпочтение модели между вариантами ответа, не калиброванная вероятность достаточности свидетельства. Имя компетенции отсутствует в промпте поиска, но присутствует в отдельном промпте проверки. Отсутствие полного каталога в промпте не означает, что время и память всей системы не зависят от каталога: построение индекса и его хранение зависят от его размера.

Источники: [`selection.py`](https://github.com/JGSnapp/krm-logit-mask/blob/d7db10cb5b1361e77862efe1e6091decec800bac/src/krm_mask/selection.py), [`wordbag.py`](https://github.com/JGSnapp/krm-logit-mask/blob/d7db10cb5b1361e77862efe1e6091decec800bac/src/krm_mask/wordbag.py).

### ESCO / Skill-XL: отдельная проверка масштаба

Этот стенд проверяет **навыки, требуемые предложением вакансии**, а не компетенции, подтверждённые опытом кандидата. Предложение уже задано как готовое свидетельство: выбор цитаты не оценивается. Английский промпт `en_jobs` спрашивает, требует ли текст вакансии конкретный навык.

Каталог содержит 13 826 имён ESCO из выгрузки TechWolf; используются названия без описаний и альтернативных меток. Загрузчик добавляет отсутствующие в версии каталога метки Skill-XL как имена. По журналу development содержит 799 релевантных предложений из 55 вакансий / 3 862 метки, test — 944 из 56 / 4 465. Текущая загрузка по умолчанию исключает предложения без релевантных навыков; качество отказа на таких текстах этим прогоном не измеряется.

На первых 20 релевантных предложениях development — 76 меток, 54 уникальных навыка — автор провёл настройку Qwen 2.5 1.5B на Tesla T4. Подкаталоги детерминированно содержат все эталонные навыки этого запуска. Это условная проверка отвлекающих вариантов, а не полностью независимый от разметки выбор каталога.

Лучшие настройки для 100 и 1 000 различаются, поэтому их сравнение также не является чистой абляцией размера каталога.

## Что требуется для использования в 02.1

Это перечень открытых работ и решений для планирования, а не согласованный график экспериментов.

| Приоритет | Что выяснить или подготовить | Зачем это нужно |
|---|---|---|
| До сравнения методов | Зафиксировать commit, модель и tokenizer revision, каталог, режим, промпты, лимиты, порог, seed и оборудование; сохранить построчные ответы | Текущий CLI запускает другой пайплайн, чем веб-селектор; одних названия проекта и модели недостаточно для воспроизведения |
| До оценки на студентах | Выбрать роли, материалы и независимую экспертную разметку компетенций, цитат, личного вклада и достаточности; отделить настройку от итоговой проверки по людям/проектам | Синтетические профили и модельная разметка не заменяют эталон 02.1 |
| Первый сравнительный эксперимент | Сопоставить маскированный поиск с уже реализованными BM25 и dense retrieval при одинаковой модели проверки, доступном каталоге и бюджете | Отделить вклад поиска от эффекта LLM-проверки и ролевого ограничения |
| Проверка свидетельств | Разделить проверку по цитате и по полному документу; оценивать каждую пару «цитата — компетенция» | Текущий `quote_first` может принять компетенцию по контексту вне прикреплённой цитаты |
| Диагностика ошибок | Считать recall пула до gate, precision/recall после него, пропуски на выборе фрагментов, ложные подтверждения и долю отказов | Понять, где теряется качество: фрагменты, поиск, проверка или лимит выдачи |
| Переход к основной задаче | Добавить экспертную рубрику достаточности, учёт авторства, противоречий, повторов и объединение по требованиям роли | В прототипе нет полного профиля соответствия роли и полуавтоматического процесса проверки 02.1 |
| Отдельная проверка масштаба | Воспроизвести ESCO-настройку с сохранением полных артефактов; затем заморозить настройки для test | Восстановить проверяемые основания чисел; отделить перенос извлечения навыков от HR-оценки |
| Продолжение | Оценивать Б/С/П только по отдельной экспертной рубрике; не переносить их из раннего пайплайна в результат текущего селектора | Уровни остаются отдельным исследовательским вопросом |

При оценке цитат нужны отдельно: точность символьных позиций, наличие непустого фрагмента в источнике, смысловая релевантность и достаточность. В старом [`evaluation.py`](https://github.com/JGSnapp/krm-logit-mask/blob/d7db10cb5b1361e77862efe1e6091decec800bac/src/krm_mask/evaluation.py) `quote_substring_rate` проверяет только вхождение строки; пустая строка тоже входит в любой текст. Этот показатель сам по себе не является оценкой качества свидетельств.

Для научного позиционирования следует проверять вклад комбинации «выбор фрагмента → поиск через признаки каталога → независимая по этапу проверка» и её компромисс качества/стоимости. Ограниченное декодирование и выбор сущностей по префиксу сами по себе не устанавливают новизну. Литературные утверждения из журнала Кирилла требуют отдельной проверки первоисточников; данный обзор не является новым literature review.

Проект требует Python 3.10+. Для окружения с `uv`, из корня клона Кирилла:

```bash
# Проверки без загрузки весов модели; torch-зависимые тесты могут быть пропущены.
uv sync --extra dev --extra web
uv run pytest -q

# Инференс требует отдельных зависимостей и весов модели.
uv sync --extra gpu --extra lemma --extra web --extra dev
uv run krm-mask serve --catalog data/itmo_krm_3.json \
  --model Qwen/Qwen2.5-1.5B-Instruct

# Development Skill-XL: готовые предложения, поиск и проверка YES/NO.
uv run python experiments/run_skill_xl_eval.py --limit 20 \
  --scale-pools 100:10,15,20,30 1000:10,15,20,30,50,75,100
```

В старой части журнала встречается `--scales`; у изученного runner актуальный параметр — `--scale-pools`. `krm-mask run` и `krm-mask evaluate` вызывают исходный `ExtractionPipeline`, а не текущий `CompetencySelector`. Для оценки позднего метода нужно использовать его runner или API с явно указанным режимом.

При локальной проверке 20.11.2026 на Python 3.12 в отдельном окружении с `pytest`, `openpyxl`, `fastapi` и `httpx` команда `PYTHONPATH=src python -m pytest -q -p no:cacheprovider -rs` дала **26 passed, 22 skipped**. Пропуски связаны с отсутствием `torch`; выдано одно предупреждение об устаревающем интерфейсе Starlette TestClient. Веса LLM не загружались, GPU-прогоны не выполнялись. Размеры каталогов и сводные количества Skill-XL сверены с локальными данными; численные результаты КРМ сверены с сохранёнными JSON. Это проверка доступных артефактов и части тестов, не воспроизведение модельных экспериментов.

При подготовке общих артефактов 02.1 достаточно ссылаться на версию каталога и согласованные производные данные: не следует автоматически переносить содержимое КРМ и персональные материалы студентов в новый публичный набор.
