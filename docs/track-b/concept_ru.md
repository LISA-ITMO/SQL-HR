# Трек B: концепция модели подтверждающих свидетельств КРМ

> Справочная постановка широкого трека B от сентября 2026. Актуальный объём первого этапа и порядок подготовки к созвону — в [README 02.1](02.1_neurosymbolic_evidence_assessment/README.md). Заявления об отсутствии аналогов в этой ранней версии требуют проверки по текущему обзору литературы.

**Источники КРМ:** описание структуры и шкал ниже относится к ИТМО 3.0. В коллекции также появилась КРМ МФТИ по ИТ — потенциальный второй источник для расширения охвата профессий ИТ и ИИ. Её структуру, версии и соответствия с ИТМО ещё нужно проверить; индикаторы и уровни нельзя автоматически объединять. Сохранять модель-источник, версию и исходный идентификатор для каждой роли и оценки. Сначала аудит и ограниченный пилот, затем решение о проверке переноса метода между моделями. Подробности: [КРМ / frameworks](frameworks/README.md).


**Рабочее название:** Операционализация компетентностно-ролевых моделей для оценки кандидатов на основе подтверждающих свидетельств

**Дата:** 18 сентября 2026 г.
**Статус:** Концептуальная переработка на основе анализа реальной структуры КРМ 3.0

---

## 1. Вклад в одном предложении

> Мы предлагаем метод операционализации компетентностно-ролевых моделей (таких как КРМ 3.0) для оценки кандидатов на основе подтверждающих свидетельств, анализа разрывов в компетенциях и объяснимого ранжирования.

**Ключевая постановка:** это **методологический вклад** (семантика операционализации), а не проект по построению графа знаний.

---

## 2. Исследовательская проблема

### 2.1 Текущее состояние (КРМ 3.0)

КРМ 3.0 — это **нормативный документ**, задающий:
- целевые профили ролей / выпускников;
- компетенции;
- индикаторы;
- уровни владения;
- рекомендации по формированию образовательных программ.

**Чего КРМ 3.0 НЕ содержит:**
- меток обязательных / желательных / исключающих требований;
- узлов подтверждающих свидетельств кандидата;
- графа пререквизитов;
- явной семантики допустимости кандидата;
- стоимости ослабления ограничений.

### 2.2 Постановка задачи

> Как можно операционализировать компетентностно-ролевую модель, предназначенную для представления целевых профессиональных профилей, для оценки кандидатов на основе подтверждающих свидетельств, анализа разрывов в компетенциях и объяснимого ранжирования?

**НЕ:**
- ❌ «Как представить КРМ в виде графа знаний» (граф — это выбор реализации);
- ❌ «Как обеспечить соблюдение обязательных / желательных / исключающих ограничений» (в КРМ они изначально отсутствуют);
- ❌ «Как построить более качественный HR-граф знаний» (уже существуют JobMatchAI, Yang & Shen 2025).

### 2.3 Научный пробел

| Существующая работа | Что делает | Чего не делает |
|---------------------|------------|----------------|
| **JobMatchAI** (демо ACL 2026) | Гибридный поиск + жёсткие ограничения + объяснения на основе графа знаний | Использует плоские списки навыков, а не структуру «компетенция / индикатор / уровень» |
| **Yang & Shen** (2025) | Построение графа знаний о талантах + предсказание компетенций | Не выполняет оценку на основе подтверждающих свидетельств |
| **Dorn et al.** (2007) | HR-онтология с уровнями компетенций и подтверждающими свидетельствами | Представляет онтологию, но не операционализирует её для поиска |
| **Работы по PJF** (Zhu, Qin, TAROT) | Резюме → предсказание соответствия вакансии | Не используют подтверждающие свидетельства и не работают на уровне индикаторов |

**Пробел:** отсутствуют работы, которые операционализируют целевые профили ролей, подобные КРМ, для оценки кандидатов на основе подтверждающих свидетельств с рассуждением на уровне индикаторов и явным моделированием неопределённости.

## 3. Предлагаемая модель сущностей

### 3.1 Основные сущности

**Сторона роли:**
```
Роль → Целевой профиль компетенций → Компетенция → Индикатор → Целевой уровень
```

**Сторона кандидата:**
```
Кандидат → Подтверждающее свидетельство → Поддержка индикатора свидетельством → Подтверждённый уровень → Разрыв в компетенции / Неопределённость свидетельств
```

### 3.2 Состояния оценки

**Минимальный набор состояний (НЕ бинарный):**
- SUPPORTED_AT_TARGET
- SUPPORTED_BELOW_TARGET
- UNKNOWN / INSUFFICIENT_EVIDENCE

**Ключевой принцип:** отсутствие подтверждающих свидетельств ≠ отсутствие компетенции.

### 3.3 Моделирование подтверждающих свидетельств

**Источники свидетельств:**
- опыт работы;
- проекты;
- образование;
- сертификации;
- другие документально подтверждённые артефакты.

**Свойства свидетельства:**
- тип источника (опыт / проект / образование / сертификация);
- подтверждаемая компетенция;
- подтверждаемый уровень;
- метаданные происхождения (provenance).

## 4. Ключевые проектные решения

### 4.1 Целевые профили на уровне индикаторов

**Проблема:** КРМ 3.0 задаёт профили компетенций для ролей, однако из этого автоматически не следует, что агрегированный уровень компетенции для роли означает одинаковый требуемый уровень для каждого индикатора.

**Наш подход:** сформулировать это как отдельную методологическую задачу — как вывести целевой профиль на уровне индикаторов из ролевого профиля КРМ.

**Требует решения:** необходима экспертная политика или эмпирическая валидация.

### 4.2 Поддержка индикатора подтверждающим свидетельством

**Проблема:** каким образом подтверждающее свидетельство поддерживает индикатор?

**Наш подход:**
- прямая поддержка (свидетельство явно демонстрирует индикатор);
- косвенная поддержка (свидетельство демонстрирует связанную компетенцию);
- отсутствие поддержки (свидетельство нерелевантно индикатору).

**Требует решения:** необходим протокол аннотирования или метод извлечения.

### 4.3 Анализ разрывов в компетенциях

**Типы разрывов:**
- BELOW_TARGET: свидетельства существуют, но подтверждённый уровень < целевого уровня;
- UNKNOWN: отсутствуют свидетельства для индикатора / компетенции;
- AT_TARGET: свидетельства подтверждают целевой уровень или уровень выше целевого.

**Ранжирование:** кандидаты ранжируются по разрыву в компетенциях относительно целевого профиля роли.

### 4.4 Объяснимость

**Типы объяснений:**
- что находится в состоянии SUPPORTED_AT_TARGET (с указанием происхождения свидетельств);
- что находится в состоянии SUPPORTED_BELOW_TARGET (с величиной разрыва);
- что находится в состоянии UNKNOWN (с указанием отсутствующих типов свидетельств).

**НЕ:**
- важность признаков (SHAP, LIME);
- веса attention;
- оценки типа «чёрного ящика».

## 5. Связь с SQL-HR

### 5.1 Что уже содержит SQL-HR

- типизированные обязательные / необязательные / запрещающие требования;
- числовые / категориальные ограничения;
- стратификацию Ideal / Fit / Fallback;
- управляемый поиск по базе данных + reranking.

### 5.2 Возможное наследование

**Слой рекрутера / запроса:**
```
Явные жёсткие / мягкие ограничения → допустимость кандидата в стиле SQL-HR
```

**Слой КРМ:**
```
Целевой профиль компетенций роли → ранжирование по разрыву в компетенциях на основе подтверждающих свидетельств
```

**Ideal / Fit / Fallback:**
- вторичный слой политики (НЕ является частью нативной семантики КРМ).

**Управляемое ослабление ограничений:**
- ОПЦИОНАЛЬНО до тех пор, пока не будет валидирована экспертная политика для минимальных / критических требований.

### 5.3 Отличия

| Аспект | SQL-HR | Трек B |
|--------|--------|--------|
| **Цель** | Реляционные предикаты | Оценка компетенций на основе подтверждающих свидетельств |
| **Семантика ограничений** | Точное соответствие (условие WHERE) | Поддержка, подтверждённая свидетельствами, с учётом неопределённости |
| **Работа с уровнями** | Числовое сравнение | Порядковая шкала с анализом разрыва |
| **Связи** | Внешние ключи | Связи между компетенциями и индикаторами |
| **Ослабление ограничений** | Не поддерживается | Опционально (требуется экспертная политика) |

## 7. Потенциальные утверждения о научной новизне

### НЕ является новизной

| Утверждение | Почему НЕ является |
|-------------|---------------------|
| Само представление в виде графа | Выбор реализации |
| Уровни компетенций | Изначально присутствуют в КРМ и других фреймворках |
| Узлы подтверждающих свидетельств | Стандартны для HR-онтологий (Dorn et al. 2007) |
| Жёсткие / мягкие ограничения в общем виде | Хорошо известны в рекомендательных системах на основе ограничений |
| Онтология компетенций | Уже существуют SFIA, ESCO, O*NET, e-CF |
| HR-сопоставление на основе графа знаний | JobMatchAI, Yang & Shen 2025 |
| Сам по себе поиск с равномерной стоимостью | Классический алгоритм |
| Сама по себе объяснимость через путь в графе | Известна в рекомендациях на основе графов знаний |

### Потенциальная новизна (требует проверки)

1. **Операционализация целевых ролевых профилей, подобных КРМ**, для оценки кандидатов на основе подтверждающих свидетельств.
2. **Привязка свидетельств на уровне индикаторов** с порядковыми уровнями владения.
3. **Явная обработка недостаточности свидетельств / неопределённости** (состояние UNKNOWN).
4. **Ранжирование по разрыву в компетенциях** относительно целевого профиля роли.
5. **Детерминированные объяснения с подробным provenance**: что подтверждено, что ниже целевого уровня, что неизвестно и какими свидетельствами это обосновано.
6. **Эмпирическая валидация:** улучшает ли анализ свидетельств на уровне индикаторов межэкспертную согласованность / качество ранжирования по сравнению с плоскими навыками и семантической близостью?
